# CR-01M0MK20: Build output cannot express the server/client classification

> **Status:** Approved
> **Triaged-by:** Richard Dale Umayan; human; v1
> **Priority:** High
> **Type:** Architecture
> **Size:** L
> **Affects:** packages/react/vite.config.ts, scripts/lib/finalize-dual.mjs, scripts/lib/bundle-record.mjs, scripts/check-exports.mjs, .size-limit.json
> **Date:** 2026-08-22
> **Created-by:** sdlc-studio file
> **Raised-by:** sdlc-studio; agent; v1
> **Raised-in-batch:** none open - raised outside a delivery batch

## Summary

Vite's library build silently drops `use client`. Measured, not theorised: a probe component carrying the directive built through our own config emitted `function Probe() { return null; }` with the directive gone, and Rollup downgraded it to a warning - `Module level directives cause errors when bundled, "use client" ... was ignored`. A warning is not a gate. Shipped as-is, every client component in Clara would arrive at a Next.js App Router consumer unmarked, and the server render crashes on the first hook.

The deeper problem is architectural, and it is why this cannot be fixed inside US-01M0GM0R. TRD Section 7 requires that client components carry the directive AND that server-capable components carry none. A single bundled chunk has exactly one top: the directive is either on everything or on nothing. Blanket-marking the bundle is spec-violating and defeats Sofia's user story - she does not want to wrap everything in a client boundary. Marking nothing is the crash. The current single-chunk output cannot express the classification the spec mandates, so the output shape has to change.

## Impact

Blocks US-01M0GM0R and PRD F23. Every client component would publish unmarked, so the first App Router consumer gets a server-render crash rather than a warning. It also blocks F01 onward: the classification has to drive the build before components exist, or each component lands into an output shape that cannot carry its own classification, and retrofitting means re-cutting every chunk.

One-way-door pressure: the output shape is reachable from the exports map, so changing it after publish is a breaking change. It is nearly free now, while nothing is published and no component exists.
