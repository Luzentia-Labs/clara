## What each round actually found

**Round 1 - the test observed a proxy, not the property.** Eight reproduced instances, every one
stamped `Verified: yes`. A class name standing in for a rendered dimension. An attribute's presence
standing in for its validity. An axe fixture rendering the control *without* the prop that triggers
the failure - the one configuration that could not fail. `expect(height).toBeTruthy()` passing on
`"0px"`, a textarea collapsed to nothing, under a test named "grows with content". An id **count**
compared where the defect was differing id **values**. Recorded as D0065.

**Round 2 - the implementation was fixed and the evidence was not.** `labelFor="group"`, the entire
fix for a Field label bound to a fieldset, appeared in no test file: deleting both halves left 751
tests and 23 gates green, while every group fixture still rendered the broken composition. Two
acceptance criteria named features that did not exist anywhere in the repo. `check:axe` named the
file holding 54 axe assertions and selected them with a pattern matching no block in it - 86
skipped, 0 run, exit 0. Recorded as D0069.

**Round 2 also caught a fix reintroducing its own defect.** `fieldChangeGuard` was installed on
`onClick` only; React derives a checkbox's change from the same native click and queues both before
either runs, so the DOM toggle reverted while `onChange` still fired reporting `checked === true`.
Recorded as D0068. Nothing caught it because no test asserted that a disabled control suppresses
anything - the model shipped without one test of its central promise.

## The technique that works

**Delete the fix and check that something goes red.** Every Critical in round 2 was found this way,
and it is now the standard for this project: a mechanism whose deletion leaves everything green is
treated as unbuilt, however correct it looks.

The corollary is cheaper still: for every assertion, ask what edit to the production code would make
it fail. Where the answer is "none", the test is decoration.

## What the reviews were right about that is uncomfortable

- The plan reviews were **retrospective** - the code was written before the plans were finalised.
  Both plan reviewers said so unprompted and correctly treated it as weakening an approval. That is
  a process defect in this epic, not a reviewer complaint.
- The a11y gap register **predicted** the `form-field-multiple-labels` miss, and the epic then
  shipped a fixture that triggered it. A prediction that comes true unnoticed is worse than none.
- Three of the guards that failed open were written *in this epic*, by the author, on the same days
  as decisions warning against exactly their failure mode.

## Where the remaining risk is

- **Appearance is unverified.** Gate 7 (visual regression) is unwired, owned by US-01M0WSME. Nothing
  in this repo can see what a control looks like; jsdom computes no layout. The shape contract in
  `check-component-css.mjs` sees only that the rules giving a control a box exist.
- **Screen reader output is unverified.** axe reads the accessibility tree, not what NVDA or
  VoiceOver say. Two manual criteria remain, both correctly marked manual.
- **Storybook stories do not exist.** The app is a bare `package.json`. Owned by US-01M0GMZW.

These are named in every verification record's Stated gaps rather than left implicit, and the
guard now fails a record whose Stated gaps section has no content.
